## 0. 现状与目标

| 现状 | 目标 |
|------|------|
| 仅 `ADMIN` / `MUNICIPAL_STAFF`，JWT 不含角色，接口无分权 | 六类角色码 + 服务端鉴权 |
| 工单批准即下发；AUTO 很少进 PENDING | 农艺审批 → 种植员接单执行 → 回填完成 |
| 全员同一套 UI | 按角色默认首页 + 能力显隐 |
| 无权限申请 / 联系 / 报告 | 三类协同对象与工单联动 |

演示期可用「一账号切换角色」或「六演示账号」；**鉴权必须以服务端角色为准**。

条件说明：

1. 农艺默认可关本区 AUTO；开全区 AUTO 建议场长确认或记审计。  
2. 场长可切换已发布配方，不可改硬限数字。  
3. 学员仅在 **沙箱区**（如 `ZONE-SIM`）可调气候/执行器；生产区只读。  
4. 农艺对 ≥阈值动作：优先走工单审批，紧急可「审批并指派」。  
5. 运维仅在 **维护窗**（`maint_window` 权限申请通过）内可高开度调试。  
6. 种植员遮阳：仅执行已批准工单档位，或阈值内 ±1 粗档（若产品允许）。  
7. 场长可代批紧急工单；日常应由农艺批。  
8. 运维可接「设备类」工单（离线、标定），不接农艺调光单。  
9. 农艺可批「配方相关 / 紧急补光」类申请；跨区策略类归场长。  
10. 学员报告 = 实训作业，需农艺或场长批阅。

### 阈值（与配方对齐）

- `approveDimAbove` / `approveShadeAbove`（默认 80）→ 超过则 **必须** 进工单，禁止直发。  
- 小步 AUTO（&lt; 阈值）可免审批，仍写控制日志。

## 4. 协同对象与关联

### 4.1 工单 `gh_work_orders`（扩展）

**状态机：**

```
PENDING ──approve──► APPROVED ──claim──► IN_PROGRESS ──complete──► COMPLETED
   │                     │
   └──reject──► REJECTED  └──（超时未接单）──escalate──► 场长通知
```

| 字段（新增建议） | 说明 |
|------------------|------|
| `created_by` / `source` | `RULE` / `MANUAL` / `PERM` / `OPS` |
| `approver_id` / `assignee_id` / `completer_id` | 审计责任人 |
| `wo_type` | `LIGHT_DIM` / `SHADE` / `DEVICE` / `MAINT` |
| `zone_id` / `target_device_sn` | 已有 |
| `linked_perm_id` / `linked_report_id` | 可选外键 |
| `note_grower` | 种植员回填 |

**谁驱动谁：**

| 触发 | 创建 | 审批 | 执行 | 完成 |
|------|------|------|------|------|
| 规则大开度 | 系统 | 农艺（场长可代） | 种植员 | 种植员 |
| 农艺手动建议 | 农艺 | 可自批或场长 | 种植员 | 种植员 |
| 设备离线/标定 | 系统/运维 | 场长或运维组长* | 运维 | 运维 |
| 权限申请通过需落地 | 系统 | —（申请已批） | 按类型指派 | 执行人 |

\* MVP 可简化：设备工单运维自批自办，场长抄送。

**与现实现差异（实现时改）：**  
`approve` **不得**直接下发执行器；仅改状态为 `APPROVED` 并通知种植员。下发发生在 `claim`→执行或显式 `execute`。

### 4.2 权限申请 `gh_perm_requests`（新建）

| 字段 | 说明 |
|------|------|
| `id`, `requester_id`, `role_at_request` | 申请人 |
| `req_type` | `EMERGENCY_CTRL` / `MAINT_WINDOW` / `SANDBOX_ZONE` / `REPORT_EXPORT` / `ROLE_TEMP` |
| `scope` | zone / device / 时长（如 2h） |
| `reason`, `status` | `PENDING` / `GRANTED` / `DENIED` / `EXPIRED` |
| `decider_id`, `decided_at` | 审批人 |
| `grants_json` | 临时能力列表 + 过期时间 |
| `linked_wo_id` | 批准后自动生成的工单（可选） |

**典型流：**

1. 种植员欠光紧急 → 申请 `EMERGENCY_CTRL`（2h 内可超阈值调光）→ 农艺/场长批 → 写临时 grant → 操作进审计。  
2. 运维换灯 → `MAINT_WINDOW` → 场长批 → 窗内暂停该区 AUTO + 允许 `dev.debug`。  
3. 学员要做遮阳实验 → `SANDBOX_ZONE` → 场长批 → 绑定 `ZONE-SIM`。

### 4.3 站内联系 `gh_messages`（新建，轻量）

| 字段 | 说明 |
|------|------|
| `from_id`, `to_id` 或 `to_role` | 点对点或角色广播 |
| `thread_type` | `WO` / `PERM` / `ALARM` / `REPORT` / `GENERAL` |
| `ref_id` | 关联工单/申请/报告 id |
| `body`, `created_at`, `read_at` | |

用途：工单驳回原因、催办接单、告警 @场长、报告批阅意见。不做独立 IM。

### 4.4 报告 `gh_reports`（新建）

| `report_type` | 作者 | 读者 | 内容要点 |
|---------------|------|------|----------|
| `DAILY_LIGHT` | 农艺（可自动草稿） | 场长、种植员 | DLI、目标达成、工单摘要、产量指数、电费估 |
| `ENERGY_YIELD` | 农艺/场长 | 场长 | 平衡分、遮阳/补光策略复盘 |
| `DEVICE_HEALTH` | 运维 | 场长、系统 | 离线次数、标定、维护窗 |
| `TRAINING` | 学员 | 农艺/场长批阅 | 沙箱实验步骤与结论 |

报告可 **引用** 当日工单 id 列表、economics 快照、权限申请结果。

## 6. API / 鉴权落地要点（实现清单）

1. JWT 增加 `role`（或查库）；拦截器后 `RoleGuard` / 方法级 `@RequireCap`。  
2. 禁止注册自选 `SYS_ADMIN`；角色仅系统管理员可改。  
3. 工单 API 按能力拆分：`approve`≠`execute`≠`complete`。  
4. 大开度：`applyDimToAll` 在非免审路径 **创建 PENDING**，不直发。  
5. 前端：`auth.can('wo.approve')`；路由 `meta.roles`。  
6. 种子六账号；登录页可选「演示角色」快捷入口。

## 7. MVP 分期

| 期 | 内容 |
|----|------|
| **R1（答辩最小分权）** | 四角色码（场长/农艺/种植员/运维）+ 服务端接口守卫 + 工单 approve/claim/complete 分权 + UI 显隐 |
| **R2** | 权限申请 + 临时 grant；approve 不再直发 |
| **R3** | 站内联系（工单/告警线程）+ 日报告自动草稿 |
| **R4** | 学员/沙箱 + 实训报告批阅；系统管理员用户管理页 |

当前 PRD 缺口「角色码与农艺/种植员分权」对应 **R1**。
