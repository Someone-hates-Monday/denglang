## 1. 背景与目标

### 1.1 一句话

面向设施栽培的**光环境闭环**：测光 → 配方比对 → 补光/遮阳联动 → 农艺审批工单可审计。

### 1.2 成功标准（约 3 分钟演示）

1. 仿真测点上线，MQTT 遥测可见（含 `ppfd`）
2. 分区绑定铁皮石斛配方，有效光偏离目标带时自动建议动作
3. 至少一次：规则下发调光或遮阳，前端可见状态回写
4. 大开度变更走农艺审批 → 种植员工单 → 执行日志可查

Agent/RAG **不**作为 MVP 成功条件。

### 1.3 约束

| 项 | 约定 |
|----|------|
| 硬件 | 演示期全仿真；接口按商购型号写死（BOM） |
| 与路灯 | 复用鉴权/MQTT/告警模式；领域独立 |
| Agent | 可选模块，不挡闭环 |

## 5. 用户故事与验收

### US-01 测点上线

作为运维，我希望仿真 PAR 测点按契约上报，以便大屏看到实时 PPFD。

**验收：** Given 仿真适配器启动 When 发布 `…/telemetry` Then 后端落库且前端 10s 内刷新 `ppfd`。

### US-02 配方驱动调控

作为场长，我希望区光低于硬限时自动补光，以便作物不欠光。

**验收：** Given 区绑定 `dendrobium-officinale-veg-v1` 且有效 PPFD&lt;50 When 规则周期触发 Then 下发 `SET_DIMMING` 且灯 `dimmingPercent` 上升（冷却期内不抖振）。

### US-03 过光遮阳

作为农艺师，我希望 PPFD 超硬限时优先遮阳，以便防光抑制。

**验收：** Given PPFD&gt;90 When 规则触发 Then 优先 `SET_OPEN_PERCENT` 增大开度；仍过高再降灯。

### US-04 审批工单

作为农艺师，我希望大开度变更先审批，以便种植员按单执行可追责。

**验收：** Given 建议调光≥80% When 生成 PENDING 工单 Then 种植员不可直接改配方；农艺 `approve` 后指令 `source=WORK_ORDER` 下发并可在日志中查到。

### US-05 配方切换

作为农艺师，我希望一键切到金线莲配方，以便答辩展示「作物-配方」解耦。

**验收：** Given 区改绑 `anoectochilus-formosanus-biomass-v1` When 下一规则周期 Then 目标带变为 ~25–35，无需改代码。

## 6. 关键流程

### 6.1 主路径（Happy）

```
测点采样 → MQTT telemetry → 区有效 PPFD
    → 比对配方硬限/目标带
    →（小步）AUTO 下发调光/遮阳 → status 回写 → 日志 SUCCESS
    →（大步）生成建议工单 → 农艺审批 → 种植员执行/确认 → WORK_ORDER 下发 → 审计
```

### 6.2 异常路径

| 场景 | 系统行为 |
|------|----------|
| 测点离线 | DEVICE_OFFLINE；该测点不参与聚合；区仍可用其余测点 |
| 指令无回执 | COMMAND_TIMEOUT；告警；不无限重试（可配置 1 次重试） |
| 审批驳回 | 工单 REJECTED；保持原执行器状态 |
| 自动调控关闭 | 场长关 AUTO；仅 MANUAL/工单可下发 |

## 7. 可选模块槽位

| 槽位 | MVP | 说明 |
|------|-----|------|
| Agent | Could | 只读：总结今日欠光次数、解释最近一次建议原因；禁止直接控灯 |

| 真机一路 | Could | 优先建大仁科 lux 或 BH1750 |

## 8. 非功能

| 项 | 目标 |
|----|------|
| 遥测周期 | 演示 5s；超时 60–90s |
| 指令超时 | 默认 30s |
| 容差 | 调光 ±3%；遮阳 ±5% |
| 审计 | 控制日志 + 工单状态机不可物理删除 |
| 安全 | 鉴权；种植员无配方硬限写权限 |

---

## 9. 风险与替代

| 风险 | 应对 |
|------|------|
| 无真量子传感器 | `sim.par` + 文档标明 BOM 联真路径 |
| lux≠PPFD | `conversionProfile` + k 系数写在 BOM |
| 规则抖振 | `cooldownSec` + 步进限制 |
| 工期紧 | 砍 Could；3D 降为 2D 热力色块 |
