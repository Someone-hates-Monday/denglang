## 1. 问题重述

| 问题 | 说明 |
|------|------|
| Who | 设施农艺师 / 场长（重庆等寡照、夏强光地区） |
| Job | 在自然光剧烈波动下，把冠层光环境稳住在作物经济最优点，并让补光/遮阳可审计 |

| HMW | 如何用可商购传感/执行器 + 可演示的 3D 光模型，复现「测光→配方→补/遮→回写」且贴近重庆日变化？ |

## 2. 作物再评估（高价值 × 精细控光 × 光→产量研究）

评分 1–5；**综合** = 价值×0.2 + 控光精细度×0.25 + 光-产量文献×0.25 + 重庆气候契合×0.15 + 演示差异化×0.15。

| 作物 | 价值 | 精细控光 | 光→产量/品质文献 | 重庆契合 | 差异化 | 综合 | 一句话 |
|------|------|----------|------------------|----------|--------|------|--------|
| **设施草莓**（红颜等） | 5 | 4 | **5** | **5** | 3 | **4.45** | 冬补光增产文献密；寡照场景最「像真」 |
| **铁皮石斛** | 5 | **5** | 4 | 4 | **5** | **4.55** | 窄带双向控光；组培/栽培阶段配方分明 |
| **台湾金线莲** | 4 | 5 | 3 | 4 | 5 | 4.15 | 耐阴极限；适合配方切换，不宜做唯一主产 |
| **蝴蝶兰** | 4 | 5 | 4 | 3 | 4 | 4.10 | 光×氮交互好讲；催花链路更长 |
| 番茄（高架） | 4 | 3 | **5** | 4 | 2 | 3.65 | 文献最多，但同质化高、需光强、演示成本大 |
| 叶菜/生菜 | 2 | 3 | 5 | 3 | 1 | 2.85 | CEA 标配，价值与差异化不足 |

### 2.1 关键证据（摘录）

**铁皮石斛（已有配方基础，需分阶段）**

| 阶段 | 适宜光 | 证据要点 |
|------|--------|----------|
| 组培/工厂苗 | ~**60–70** µmol·m⁻²·s⁻¹；12 h | 人工光工厂试验：68 最佳，>92 光抑制；多糖在过高光下降 |
| 栽培苗人工光 | **90–120** 综合优；**150** 易抑制；12 h 优于 9 h | 干物率随光升至 120 后增益减弱 |
| 大棚经验 | 常配重度遮阴；忌强直射 | 与「补光+遮阳」双执行器叙事一致 |

**设施草莓（光→产量最「硬」）**

- 日光温室基质「红颜」：LED 补光相对对照增产约 **33–56%**（光质红蓝 9/1 最高），采收提前约 10 d；动态补光策略电能效率优于盲目高功率。  
- 国际园艺指南：草莓目标 DLI 约 **17–25** mol·m⁻²·d⁻¹；典型补光 PPFD 量级 ~150 µmol（视自然光缺口）。  

**台湾金线莲**

- PPFD **~30** 利生物量；**10** 偏黄酮；**≥60** 易受抑；地方标准棚内照度约 **1800–8000 lx** + 双层遮阳。  

**蝴蝶兰**

- 营养期常引 DLI **~4–10**、PPFD **~100–200**；催花与光谱/低温耦合；**氮肥 × DLI** 交互显著——适合讲「多传感器改光策略」。  

### 2.2 作物结论（修订冻结建议）

| 角色 | 作物 | 理由 |
|------|------|------|
| **演示主叙事（精细双向控光）** | 继续 **铁皮石斛** | 综合最高；必须强调**阶段配方**（组培 60–70 vs 栽培 90–120），避免单一硬限 |
| **气候/产量叙事（重庆冬寡照）** | 新增 **设施草莓** 为第二主配方 | 光→产量论文与产业补光最贴近「实景」 |
| **配方切换辅作物** | 金线莲 | 耐阴对照，不变 |
| **Should 交互叙事** | 蝴蝶兰或草莓「高氮降光」规则 | 展示光×肥，不扩成水肥全平台 |

> **不要**改成「只做番茄大棚」：文献虽多，实训同质化与功耗/均匀度演示负担更大。

**灯光排布模型（工程分层）**

```
L0 几何：棚体尺寸、透光率、内/外遮阳、灯具坐标与高度、冠层测点网格
L1 光学（MVP）：解析/预计算「单灯→网格」响应矩阵 A；dimming 向量 d → PPFD = A·d + τ·E_sun(t)
L2 光学（Stretch）：Radiance/HLS 离线烘焙日型场景（晴/雾/夏正午）
L3 控制：配方目标带 → 求满足 ||PPFD-target|| 与能耗的 d、shade%
L4 呈现：Three.js 棚体 + 灯具 + 冠层平面伪彩 PPFD（读网格值，不读贴图像素）
```

## 4. 重庆光照曲线（模拟数据源设计）

### 4.1 气候事实（用于答辩口径）

- 盆地雾多；主城年日照常见 **约 900–1200 h**（沙坪坝站多年平均约 **954 h**；区域材料或写 1000–1400 h）。产量/电费/规范细表见 [CROP-ECONOMICS-STANDARDS-REF.md](./CROP-ECONOMICS-STANDARDS-REF.md)。  
- 冬春弱光高湿、夏高温强光；设施痛点：**冬季补光增值大**；**夏季遮阳+通风**优先于硬补光。  

### 4.2 仿真输入（不编造「假气象站」）

| 输入 | 来源策略 |
|------|----------|
| 室外水平面辐射 / 日照时数 | 优先公开气象再分析或气象局典型年；MVP 用**参数化典型日**（冬雾、冬晴、夏晴、夏阴） |
| 棚内自然光 | `E_in = E_out × τ_cover × τ_shade(open%) × f_diffuse` |
| 补光 | `E_led = A · dimming`（§3） |
| 冠层有效 | `PPFD_eff = E_in_PAR + E_led`（测点或网格平均/最小） |
| DLI | 日积分 `Σ PPFD·Δt × 0.0036` |

### 4.3 MVP 典型日模板（可配置 JSON）

| profileId | 用途 | 行为特征 |
|-----------|------|----------|
| `cq-winter-fog` | 主演示 | 正午棚内自然 PPFD 很低 → 长时补光拉 DLI |
| `cq-winter-clear` | 对照 | 午间自然光可用，补光「填谷」 |
| `cq-summer-noon` | 遮阳演示 | 正午过高 → 先遮阳再降灯 |
| `cq-overcast` | 春秋 | 全天缺口中等 |

**禁止**：把 lux 曲线直接当 µmol 而不声明 `conversionProfile`。

## 5. 多传感器如何「对应调节光照」（贴近实景、仍以光为主）

原则：**光是主执行量**；温湿/水肥是**门控与目标修正**，本期不做水肥闭环执行（除非 Stretch 仿真记录）。

| 传感/记录 | 对光策略的作用 | MVP | Should |
|-----------|----------------|-----|--------|
| PPFD / lux | 主反馈 | Must | — |
| 气温 + 相对湿度 → **VPD** | 高 VPD：限制猛补光（减蒸腾胁迫）；低 VPD：可稍提高目标 | 计算展示 | 改 `ppfdTargetMax` 动态 |
| 土湿 / 基质含水 | 干旱：禁止抬 DLI；优先告警灌溉 | 只读告警 | 与工单联动 |
| EC / 施肥记录 | 高光需足够营养：EC 过低则**封顶调光**并提示农艺 | 规则门控 | 蝴蝶兰「高氮降 DLI」故事 |
| 土质/基质类型（档案） | 不同持水与盐分缓冲 → 选配方族 | 静态档案 | — |
| CO₂（可选） | 高 CO₂ 提高光饱和利用 | Won't/Could | — |

**协同伪规则（答辩可讲）**

```
target = recipe.ppfdTarget
if VPD > vpdHigh: target *= 0.85; preferShade = true
if substrateMoisture < moistMin: forbidIncreaseDimming = true; alarm IRRIGATION
if EC < ecMinForHighLight and dimmingDemand > 60%:
    capDimming = 50%; createAgronomistHint("营养不足，不宜强补光")
apply Chongqing sun(t) + shade + dimming with cooldown
```

## 6. 解决方案架构（贴近实景的分层）

```
┌─────────────────────────────────────────────────────────┐
│ 演示前端：3D 棚体 + PPFD 热力 + 重庆日型切换 + 工单      │
└───────────────────────────┬─────────────────────────────┘
                            │ REST / WS
┌───────────────────────────▼─────────────────────────────┐
│ 光棚域服务：Recipe · Zone · WorkOrder · ControlLog        │
│ 规则：硬限 / 目标带 / 多传感门控 / 审批阈值               │
└─────────────┬───────────────────────────┬───────────────┘
              │ MQTT                      │
     ┌────────▼────────┐         ┌────────▼────────┐
     │ 设备适配器层     │         │ 光环境仿真器     │
     │ sim.* / 真机 BOM │         │ 重庆曲线+矩阵A  │
     └─────────────────┘         └─────────────────┘
```

### 6.1 MVP（答辩 3 分钟闭环）

1. 双配方：**石斛（分阶段）** + **草莓（重庆冬）**；金线莲一切换。  
2. 仿真器播 `cq-winter-fog` / `cq-summer-noon`。  
3. 测点/网格有效 PPFD → 补光或遮阳 → status 回写 → 日志。  
4. 大动作审批工单。  
5. **3D 视图**：简化棚体 + 灯具方块 + 冠层平面伪彩（数据来自预计算网格或实时 A·d）。  

### 6.2 Should

- VPD / 含水 / EC **门控**（仿真传感器即可）。  
- DLI 日曲线与「今日是否达标」。  
- 响应矩阵布灯：改灯高/间距即时刷新热力。  

### 6.3 Stretch / Won't

- Stretch：Radiance 离线烘焙；真机一路 PAR。  
- Won't：全自动水肥机、多园区、Agent 直接控灯。

## 7. 假设与风险

| 假设 | 影响 | 不确定 | 本周可测 |
|------|------|--------|----------|
| 组培 vs 栽培石斛配方分阶段被评委接受 | H | L | 更新 light-recipe 两版 ID |
| 解析/矩阵光学够答辩（无需实时 Radiance） | H | M | 做 1 张均匀度对比图 |
| 重庆典型日参数与真实气象偏差 | M | H | 标注「典型日模板」来源与可替换接口 |
| 多传感规则过度复杂导致演示失败 | H | M | 门控默认关闭，一键演示开 |

**Demo killers：** 实时重型光追、依赖外网气象、真机未到却写死联调。

## 8. 裁决与下一步

1. **主叙事仍用铁皮石斛（精细双向控光）**，配方改为**分阶段**；**设施草莓作为重庆寡照产量叙事第二配方**。  
2. **3D**：产品演示走 Three.js + PPFD 网格；光学真源走响应矩阵，Radiance 仅离线资产。  
3. **重庆**：四套典型日驱动自然光项；夏遮冬补。  
4. **多传感**：温湿→VPD、土湿、EC/施肥记录作光策略门控，不抢光闭环主权。
