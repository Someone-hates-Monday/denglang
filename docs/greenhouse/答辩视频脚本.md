## 2. 口播全文（可直接照着念）

> （镜 2）重庆寡照多雾，设施作物长期欠光，补光遮阳全凭人工经验。我们做的这套平台，把测光、比对、调控、审批串成闭环。
>
> （镜 3）打开冠层光场，3D 棚体实时显示灯位与冠层 PPFD 热力；右边全日光照曲线随重庆日型仿真推进——一天压缩到 120 秒。
>
> （镜 4）配方按作物解耦：切到金线莲，目标带立刻变为 25 到 35，无需改任何代码；主作物铁皮石斛组培 60 到 70、栽培 90 到 120。
>
> （镜 5）当建议调光达到 80% 以上，系统不再直接执行，而是生成待审批工单——防止误操作造成强光灼伤。
>
> （镜 6）审批和执行分离：农艺师批准不等于下发，种植员接单执行后，指令才真正下发，控制日志全程可查——权责可追溯。
>
> （镜 7）底层通过 MQTT 与 EMQX 通信，遥测 5 秒一报；设备页展示在线与指令状态，数据落 PostgreSQL。
>
> （镜 8）内置农艺助手，输入“石斛怎么养”“大棚多大”都能直接回答，方便现场与实训使用。
>
> （镜 9）配套从零到跑通的部署文档：WSL、Docker、初始化数据库、后端一键启动，换台新机器也能按文档部署成功。
>
> （镜 10）团队六人覆盖后端控光、前端光场、数据、角色权限、需求架构与部署交付，完整交付了源码、数据库、发布包、部署与开发文档。
>
> （镜 11）谢谢观看，欢迎提问。

## 3. 录制提示

- **镜头 4/5/6 是关键演示**：提前用 `sim/reset-day` 重置日型，卡好时机让"欠光→补光→大开度→工单"自然发生。
- 录屏前确认 `.env.local` 为 `VITE_API_MODE=http`（连真后端），避免 Mock 模式下工单不流转。
- 录完后剪掉等待片段，保持节奏；每镜可加 1s 淡入淡出。
- 导出 MP4（H.264 + AAC），文件名建议 `智慧光棚-答辩视频.mp4`。
