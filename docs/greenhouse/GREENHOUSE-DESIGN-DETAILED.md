## 1. 理论与规程依据（摘要）

| 主题 | 结论（用于本示范棚） | 来源口径 |
|------|----------------------|----------|
| 棚型 | 单跨钢架拱棚，宽约 **6–8 m**；本设计取 **7 m** 宽、**16 m** 长 | 雁荡山铁皮石斛设施规程类：棚宽 6/8 m、拱杆间距、离地苗床 |
| 苗床 | **高架栽培**，床面离地 **≥0.50 m**；畦宽约 **1.2–1.5 m**（本设计床宽 0.80 m 便于双区演示） | 同上；利于通风、防积水（石斛忌闷湿） |
| 遮阳 | **外遮阳网**遮光率约 **50–65%**（活动式）；强光季可再加内层；石斛要「半阴半阳」 | 规程遮光率 + 产业实践（夏遮、冬收） |
| 补光 | LED 吊于冠层上方约 **0.3–0.5 m**；日补光时常约 8–12 h（配方控制） | 设施补光工程惯例 + 本项目光配方 |
| 朝向 | 中低纬温室常见争论：**东西长轴**利于冬半年南侧均匀受光；重庆冬雾补光叙事优先南侧长边 | 设施农业朝向教材共识 + 本项目气候叙事 |
| 传感 | 冠层上方测光；温湿度计常挂苗床上方 **0.3–0.4 m** | 规程温湿度计挂高；本项目 PAR 用冠层平面 |

## 2. 朝向（冻结并可视化）

```
        北 (+Y)
         ↑
  西 ←───┼───→ 东 (+X)   长轴 = 东西
         ↓
        南 (Y≈0，正午主采光面)
```

| 决策 | 说明 |
|------|------|
| 长轴东西 | 南侧长边全日受光路径最长；南床 / 北床形成自然光梯度，方便演示均匀度与补光 |
| 南门外走道 | ≥1.2 m，作业与参观主入口 |
| 东西山墙 | 门 + 电控柜；电缆沿**北檐内侧**走线，减少南侧遮光 |

3D 视图必须可见：**南·采光 / 北 / 西·ZONE-A / 东·ZONE-B** 方位标（已实现）。

## 3. 作物「叠放」与床位结构

「叠放」在本棚指 **垂直分层栽培面**，不是无序堆叠：

### 3.1 ZONE-A · 铁皮石斛（双层）

| 层 | 高度 | 内容 | 光环境意图 |
|----|------|------|------------|
| **L0 栽培层** | 床面 `zBed=0.55`；冠层顶 ≈ **0.90** | 栽培苗丛植/盆栽，3 条东西向床 | 目标带 90–120（栽培配方）或 60–70（组培配方切换） |
| **L1 组培/炼苗层** | 搁架顶 ≈ **1.25**（仅中床、北床上方局部） | 组培瓶苗/穴盘，密度高、需更稳弱光 | 偏漫射；外遮阳收起时仍靠北床+局部内衬网（示意） |

南床 **不设 L1**，留给最强自然光下的栽培对照。

种植示意（每床沿 X）：盆栽间距约 **0.35 m**，两列错位；3D 用实例化盆栽代理体即可。

### 3.2 ZONE-B · 金线莲 / 草莓切换

| 模式 | 床面 | 作物形态 | 灯策略 |
|------|------|----------|--------|
| 金线莲（默认） | `zBed=0.55`，冠层矮 ≈ **0.75** | 床面密植耐阴草本 | 低 PPFD 目标；灯峰值较低 |
| 草莓（切换） | 同床改为 **高架槽式** 叙事（几何仍用床框） | 槽栽，冠层略高 ≈ **0.95** | 强调 DLI 与冬补光 |

两模式 **共用灯/测点坐标**；切换只改配方与测光平面名义高度。

## 4. 灯光与作物对应（一对多映射）

原则：**灯位对齐床轴，不对准走道中心**；半角 60° 覆盖相邻床缝。

### ZONE-A（4 灯 · 2×2）

| 灯 | 主要服务床 | 次要覆盖 |
|----|------------|----------|
| LAMP-ZONE-A-01 (2.0, 2.35, **1.45**) | BED-A-S + 中床南沿 | L0 栽培 |
| LAMP-ZONE-A-02 (2.0, 5.35, **1.45**) | BED-A-N + 中床北沿 | L0 + L1 北侧 |
| LAMP-ZONE-A-03 (6.0, 2.35, **1.45**) | BED-A-S 东段 | 同左 |
| LAMP-ZONE-A-04 (6.0, 5.35, **1.45**) | BED-A-N 东段 | L0 + L1 |

灯高 **1.45 m** ≈ 冠层顶 0.90 上方 **0.55 m**（符合 0.3–0.5 m 工程带上限，兼作业净空）。

### ZONE-B（3 灯 · 品字）

| 灯 | 主要服务 |
|----|----------|
| LAMP-ZONE-B-01 / 02 | 西段南/北床 |
| LAMP-ZONE-B-03 | 东段中轴补均匀度 |

灯高同 **1.45 m**；`maxPpfdAtCanopy` 140（耐阴作物防过曝）。

3D：灯具画为 **条形灯盘 + 锥形光柱** 指向对应床，而非仅一个黄球。

| 测点 | 位置逻辑 | Z |
|------|----------|---|
| PAR-*-01 | **南床**冠层上，偏西/中 | A: **0.90** / B: **0.78** |
| PAR-*-02 | **中床**中央，代表区平均 | 同上 |

## 6. 遮光：用什么、遮哪边、怎么看见

### 6.1 选型（与 BOM 一致）

| 层 | 材料 | 遮光率 | 安装位置 | 驱动 |
|----|------|--------|----------|------|
| **外遮阳（主）** | 黑色/铝箔编织遮阳网（耐老化） | 设计 **55%** 标称；控制用 `maxBlockFraction=0.85` 含重叠/老化余量 | **拱顶外侧**脊下卷轴，Z≈3.50 | 创明众联 B 类，半跨独立：`SHADE-ZONE-A/B` |
| **内遮阳（辅·示意）** | 轻质白/黑网 | ~70–75%（金线莲极限耐阴） | 仅 ZONE-B 北床上方局部，MVP 可不接 MQTT | 手动/远期 |

**语义（与 MQTT 一致）：**  
`shadeOpenPercent=100` → 网**收起**在**北侧卷轴盒**（最大透光）；  
`=0` → 网自北向南（或自脊向两侧）**满展**覆盖该半跨。

### 6.2 遮哪边

- 遮的是 **整半跨屋面投影**（西 0–8 m / 东 8–16 m），不是单床局部。  
- 夏正午：优先降外遮阳开度（网展开）；冬雾：网收起 + LED 补光。  
- 南侧长边仍是自然光入口；外遮阳在膜外削减直射，避免只靠关灯。

### 6.3 视图要求（必须可见）

1. 半透明**网格遮阳布**（非纯黑平面），展开面积随 `1 - open%/100` **连续变化**。  
2. 北侧可见 **卷轴/电机盒** 小几何体。  
3. 标签：「外遮阳 55% 网」。  
4. 收起时布料缩到北侧一条，展开时盖住拱下投影。

## 7. 可借鉴的现成 3D / 光模拟项目

| 项目 | 技术 | 我们怎么用 |
|------|------|------------|
| **[horticulture-lighting-simulator](https://github.com/luminousphotonics/horticulture-lighting-simulator)**（Luminous Photonics） | Radiance + **Three.js Assembly Viewer** + GLB 灯具 | **首选参考**：PPFD 层、灯具 LOD、植物接收面；MVP 学其「网格伪彩 + 灯具资产」，Stretch 可离线烘焙 |
| [MeadowMakerAi/greenhouse-cannabis-model](https://github.com/MeadowMakerAi/greenhouse-cannabis-model) | React + R3F，太阳天文位置、24h 钟 | 借鉴日轨/天空；作物模型勿直接抄商业条款 |
| kody-w greenhouse-tropical / storm（Three 单页） | 氛围向温室 + 着色器 | 仅作「棚体氛围」灵感，非农艺真源 |
| CGTrader Greenhouse Pack 等 | Blender / **UE5** 模块化温室资产 | **资产管线**：Blender 建模导出 **GLB** → Three；UE 用于答辩 cinematic，不进控制闭环 |
| Epic Digital Twin 教程 | UE + 外部 JSON/API | 远期「炫酷数字孪生」可选；IoT 控制仍走 Web+Spring |

### 7.1 技术路线决策（冻结）

| 阶段 | 方案 | 理由 |
|------|------|------|
| **现在 · 控制台 MVP** | **Three.js**（现 Vue 页）+ 布局 JSON 驱动几何；遮阳/作物/灯代理体 | 与 MQTT/仿真同源、浏览器零安装、课程可改 |
| **短期增强** | Blender 建「cq-demo-bay」低模 → **GLB** 替换代理棚体；灯具用简单 CAD 灯盘 | 观感接近 HLS Viewer，仍读同一坐标真源 · **已接通**：见 [GLB-PIPELINE.md](./GLB-PIPELINE.md)，`npm run bake:glb` |
| **答辩可选** | UE5 导入同一 FBX/GLB + 读 `/greenhouse/.../effective-light` | 电影级光照；**不**替代业务前端 |
| **不做** | 把 Radiance/UE 塞进每秒控制环 | 时延与答辩风险过高；矩阵光学足够 |

结论：**Three.js 功能够控制台**；不够「电影级」时用 **Blender 出模 +（可选）UE 展陈**，而不是推翻 Web 栈。
